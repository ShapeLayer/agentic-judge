# 설치형 문제풀이 UI

`app/`의 HTML·CSS·TypeScript 앱을 Rust 바이너리에 내장합니다. `agentic-judge serve --open`으로 실행하며 같은 서버의 HTTP API를 사용합니다. 현재 동작은 [UI-SPEC.md](../docs/UI-SPEC.md), 화면 구성은 [UI-DESIGN.md](../docs/UI-DESIGN.md)에 문서화되어 있습니다.

| 파일 | 역할 |
|---|---|
| `app/index.html` | 문제 검색 창, 본문, 코드 작성·제출, 결과, 채점 준비 폼 |
| `app/app.ts` | API 호출, 문제 선택, 초안 저장·복구, 파일 열기·다운로드 |
| `app/types.ts` | 앱에서 사용하는 API 응답 필드의 TypeScript 타입 |
| `app/app.css` | 레이아웃·컨트롤·반응형 스타일 |
| `styles/tokens.css` | 색상·시스템 글꼴과 라이트/다크 토큰 |
| `../src/web_ui.rs` | HTML, 컴파일된 스크립트, CSS를 내장하고 URL에 매핑 |

## 개발과 빌드

Node.js 22 이상과 npm이 필요합니다.

```sh
npm ci --prefix ui
npm run check --prefix ui
npm run build --prefix ui
cargo run -- serve --open
```

`tsconfig.json`으로 strict 검사 후 `build.mjs`가 Monaco와 에디터 worker를 포함한 ES 모듈 및 CSS를 `dist/app/`에 번들합니다. `.ts`의 `.js` import 경로는 출력 모듈 기준입니다. `npm run watch --prefix ui`로 변경 사항을 자동 번들할 수 있습니다. HTML과 정적 자원은 바이너리에 내장되므로 변경 사항을 서버에 반영하려면 Cargo를 다시 빌드하고 서버를 재시작해야 합니다. API가 필요하므로 정적 파일 서버만으로 앱을 실행할 수 없습니다.

최초 npm 의존성 설치 후 `cargo build`/`cargo test`는 `build.rs`에서 UI를 오프라인 컴파일합니다. `dist/`와 `node_modules/`는 버전 관리하지 않습니다. 배포 바이너리 사용자는 Node.js와 npm이 필요하지 않습니다.

풀이 코드는 로컬에 번들된 Monaco 에디터에서 작성합니다. 상단 **문제 찾기**에서 번호·이름·태그를 검색하고 50개 단위로 이동합니다. 검색 API는 최대 100개만 반환하며, 서버는 변경되지 않은 문제 메타데이터를 재사용합니다. 다른 세션에서 가져온 문제도 다음 검색이나 새로고침에 반영됩니다.

상단 **전체 제출 기록**에서 모든 문제의 제출을 최신순으로 20개씩 볼 수 있습니다. 문제 번호·이름, 판정, 언어 필터와 문제 열기를 지원하며 상세 미리보기와 전체 기록 다운로드는 문제별 기록과 동일합니다.

제출 기록은 코드와 평가 결과만 저장합니다. 테스트 데이터는 각 보기 항목을 펼칠 때 앞 4,096자와 실제 파일 경로를 제공합니다. 실행 결과 파일은 문제의 `submission-data/`에 분리되어 있으며 빌드·실행 임시 폴더는 처리 후 제거됩니다. 기존 기록 정리는 `agentic-judge call --config /path/to/config.toml submissions_compact '{}'`로 수행할 수 있습니다.

최초 접속, 문제 선택, 화면 새로고침과 문제 데이터 재조회 중에는 로딩 오버레이에 현재 작업 및 완료 단계 기준 진행률을 표시합니다. 문제 데이터 조회에는 설명·예제·테스트 목록·채점 준비 상태 확인이 포함되며, 생성 모델·검정 기록과 최근 제출 기록도 별도 단계로 표시합니다. 진행률은 전송 바이트 비율이 아닙니다. 오류가 발생하면 오버레이를 닫고 화면의 상태 메시지에 오류를 표시합니다.

채점 준비는 준비 현황과 풀이 코드·테스트 데이터·검증 실행·모델 기록·문제 설명으로 구성합니다. 기대 판정을 지정한 코드의 검증 실행과 입력 검증기의 정상/비정상 입력 검사는 준비 탭에서 확인합니다. 일반 채점 결과 및 전체 제출 기록에는 풀이 제출만 표시하며, 완료된 기록은 버튼으로 양쪽에 이동할 수 있습니다. 준비용 데이터는 해당 탭 진입 시 불러옵니다.

채점 결과 목록에는 판정·통과 테스트 수·최대 시간/메모리·코드 크기를 요약하며 판정/언어 필터와 새로고침을 제공합니다. 상세에서 전체/실패 테스트를 선택하고 코드·결과를 확인할 수 있습니다. 제출 목록의 큰 데이터는 요청하지 않고 기존 기록의 요약 수치는 요청 페이지에서만 계산해 캐시합니다. 목록/상세의 사용량 및 코드 크기 흐름은 [DOJ 채점 현황](https://doj.kr/ko/status)을 참고했습니다.
