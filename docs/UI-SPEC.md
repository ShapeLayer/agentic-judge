# 현재 UI 기능

이 문서는 `ui/app/index.html`과 `ui/app/app.ts`에 구현된 설치형 문제풀이 화면을 설명합니다. `agentic-judge serve --open`으로 실행하며, 서버가 바이너리에 내장한 자원을 제공합니다. 실행 경로와 세션 정책은 [INSTALLATION.md](INSTALLATION.md), 화면 구성은 [UI-DESIGN.md](UI-DESIGN.md), 빌드는 [ui/README.md](../ui/README.md)를 참고합니다.

## 탐색과 문제 조회

앱은 `/` 또는 `/index.html`의 단일 화면입니다. 문제 선택 시 URL을 `#<인코딩된 문제 ID>`로 바꾸며, 초기 로드에서 해당 문제를 복구합니다. 별도 문제·답안·테스트 상세 URL이나 탭 라우터는 없습니다.

상단 **문제 찾기** 버튼은 검색 대화상자를 엽니다. `problems_search`로 이름·ID·태그를 대소문자 구분 없이 검색하며 250ms 입력 지연과 50개 단위 페이지 이동을 제공합니다. 서버는 최대 100개만 반환하고 변경되지 않은 문제 메타데이터를 재사용합니다. 문제 선택 후 창은 닫히며 상시 사이드바는 없습니다. 문제를 선택하면 이름, ID, 시간 제한(ms), 메모리 제한(MiB), `problem_get.ready`에 따른 준비 여부를 표시합니다. 본문은 legend/input/output/notes 중 Markdown이 있는 섹션의 서버 정화 HTML을 표시하고, 예제 입력·출력을 순서대로 보여 줍니다. 수식은 서버가 반환한 MathML로 표시합니다.

## 코드 작성과 초안

풀이·정해 코드 입력은 Monaco 에디터이며 언어별 구문 강조, 줄 번호, 들여쓰기와 시스템 라이트/다크 테마를 지원합니다. 에디터와 worker는 실행 파일에 번들되어 외부 다운로드가 필요 없습니다. 언어 목록은 `capabilities.languages`에서 읽으며 초기 언어는 Python이 있으면 Python, 없으면 첫 언어입니다.

입력 즉시 localStorage에 임시 저장하고, 500ms 후 `draft_save`로 서버에 저장합니다. 저장 키는 저장소 루트·워크스페이스·문제·언어로 구분합니다. 문제·언어 전환 전에는 기존 초안을 저장하며, 복구 시 미전송 브라우저 초안을 서버 초안보다 우선합니다. 문제별 선택 언어도 브라우저에 보관합니다. 미전송 초안이 있으면 페이지 종료 경고를 요청합니다.

파일 열기는 브라우저 File API로 텍스트를 읽어 에디터에 넣고 초안으로 저장합니다. 파일 확장자가 설정된 언어 파일명과 일치하면 언어를 선택합니다. 파일 크기는 3 MiB까지이며, JSON 요청은 UTF-8 기준 4 MiB를 초과하면 전송 전에 거부합니다. 파일로 저장은 초안을 저장한 후 `/api/draft-download`에서 다운로드합니다.

워크스페이스가 연결되어 있으면 파일 목록과 상대 경로 입력으로 `workspace_read`를 호출할 수 있습니다. scratch 모드에서는 이 영역과 문제 가져오기를 숨깁니다.

## 제출과 결과

제출은 별도의 초안 저장 없이 현재 문제·언어·코드를 `submit`에 전달합니다. API는 동기식이며, 처리 중 버튼·입력·선택 요소를 비활성화하고 상태 메시지를 표시합니다. 실패하면 서버 오류를 표시합니다. 제출 실패 시에는 기록을 다시 조회하고 재시도 전에 기록을 확인하도록 안내합니다.

제출 목록은 생성 시간 역순의 요약 20개씩이며 `submissions_page`를 사용합니다. 펼칠 때 `submission_preview`로 제출 코드와 테스트별 판정·시간·메모리·종료 코드만 읽습니다. 테스트 입력·기대 출력·실행 출력·진단·체커 데이터는 각각 **보기**를 펼칠 때에만 `submission_data_preview`로 앞 4,096자와 전체 바이트 수 및 실제 절대 파일 경로를 가져옵니다. 입력·기대 출력은 현재 테스트 파일을 참조하며 제출 이후 수정될 수 있다는 안내를 표시합니다. 실행 출력·진단·체커 메시지는 별도 `submission-data/<제출 ID>/<케이스 인덱스>/` 파일입니다. 이 파일을 삭제해도 코드와 판정은 보존되며 UI는 파일 없음으로 표시합니다. **코드·평가 결과 내려받기 (JSON)**는 기록만 내려받습니다. `submissions_compact`로 기존 기록의 중복 테스트 데이터를 제거하고 실행 출력을 파일로 분리할 수 있습니다. 새 기록은 format_version=2이며 대량 문자열은 포함하지 않습니다. 빌드와 실행 임시 폴더는 성공·실패·시간 초과 시 자동 제거됩니다.

## 문제 등록과 채점 준비

| 화면 동작 | API와 저장 범위 |
|---|---|
| 문제 만들기 | `problem_create`: ID와 이름 |
| 문제 가져오기 | `problem_import`: 워크스페이스 문서 경로와 ID. 반환 경고를 준비 상태 옆에 표시 |
| 설명 저장 | `statement_set`: legend 섹션 Markdown |
| 정해 저장 | `answer_save`: 언어·코드, expected=AC, main=true. 재생성 오류 표시 |
| 테스트 저장 | `test_put`: general suite, 번호와 입력. 다음 번호는 기존 general 최댓값+1 |
| 새로고침 | 초안 저장 후 문제 목록과 선택 문제·제출 기록 재조회 |

입력·출력·노트 섹션 편집, 예제 편집, validator/generator/checker 설정, 답안 리비전·diff, AI 검증 관리는 현재 화면에 없습니다. 관련 백엔드 도구는 [API-TOOLS.json](API-TOOLS.json)의 HTTP/MCP 인터페이스 명세으로 유지합니다. 별도 테스트 상세 화면과 사용자 지정 목록 정렬은 현재 구현 범위에 포함되지 않습니다.

## 정적 자원과 접근성

서버는 `/app.js`, `/app.css`, `/tokens.css`를 내장하고 CSP로 스크립트·스타일·API 연결을 동일 출처로 제한합니다. 외부 CDN이나 폰트를 로드하지 않습니다. 본문 정화와 파일 접근 경계는 서버에서 처리합니다.

폼은 label과 기본 HTML 컨트롤을 사용합니다. 문제 검색·목록에는 접근 가능한 이름이 있고, 선택 문제에는 `aria-current`를 표시합니다. 전역 알림은 `role=status`와 `aria-live=polite`, 초안 상태는 `role=status`를 사용합니다. 상세 펼침은 네이티브 details/summary입니다.

## 전체 제출 기록

상단 **전체 제출 기록**은 모든 문제의 제출 요약을 최신순으로 20개씩 표시하는 대화상자입니다. 문제 번호·이름, 판정, 언어로 필터링하며 기록을 펼치면 상세와 코드·평가 결과 다운로드를 표시합니다. **문제 열기**로 해당 문제에 이동합니다. `submissions_page`의 `problem_id`를 생략하면 전체 문제를 대상으로 합니다.

## 작업 탭과 채점 표

선택한 문제는 **문제풀이 / 채점 결과 / 채점 준비** 탭으로 나눕니다. 문제풀이 탭에는 본문과 Monaco 에디터만 표시하며 초안은 탭 전환에도 유지됩니다. 제출 완료 후 채점 결과 탭으로 이동하고 최신 제출의 테스트별 결과를 표시합니다. 제출 목록과 테스트별 결과는 표이며 판정은 AC(통과), WA(오답), TLE(시간 초과), MLE(메모리 초과), RE, CE, PE 등을 코드·한글 이름·테마 색상으로 표시합니다. 결과 표의 **자세히 보기**는 별도 테스트케이스 상세 대화상자를 열어 시간·메모리·종료 코드와 항목별 데이터 보기를 제공합니다. 상세 진입만으로 평가 파일을 읽지 않으며 각 보기 항목을 펼칠 때 미리보기와 실제 경로를 가져옵니다. 전체 제출 기록도 동일한 표와 상세 화면을 사용합니다. 탭은 방향키·Home·End 및 aria-selected/aria-controls를 지원합니다.

### 생성 및 검정 모델 기록
별도 모델 메뉴 없이 풀이 코드 및 테스트 데이터의 각 항목 옆에 생성(✦)과 AI 검정(✓·×·!·?) 심볼을 표시합니다. 심볼의 호버·키보드 초점·클릭 툴팁은 생성 모델 또는 검정 제공자, 요청/응답 모델, 시각, 사유를 표시합니다. 생성 모델은 저장 시 제공된 정보이며 미기록 데이터는 추정하지 않습니다. 이전 내용에 대한 검정은 현재 결과에서 제외합니다.


## 채점 준비 작업과 실행 기록

채점 준비 상단에 채점 가능 여부, 기준 정해 등록, 테스트 수와 테스트 셋 수, 입력 검증기 설정을 표시합니다. 작업 영역은 풀이 코드, 테스트 데이터, 검증 실행, 모델·검정 기록, 문제 설명으로 구분합니다. 코드 목록에는 기준 정해·입력 검증기·검증용 코드 역할, 언어, 기대 판정과 버전을 표시하고 기존 코드를 수정하거나 판정을 검증할 수 있습니다. 기준 정해는 AC여야 합니다. 의도적으로 잘못된 코드에는 WA·TLE 등의 기대 판정을 지정합니다.

`test_run` 실행은 `purpose=preparation`으로 저장하며 코드 ID, 버전, 기대 판정을 함께 기록합니다. `submit`은 기본 `purpose=solve`이며, 준비용 직접 실행은 `purpose=preparation`과 `expected`를 지정합니다. 비동기 준비 실행도 동일하게 분류합니다. 문제별 채점 결과 및 전체 제출 기록은 기본적으로 풀이 제출만 표시합니다. `submissions_page`의 `purpose`는 solve(기본), preparation, all을 지원하며 필터 적용 후 페이지를 나눕니다.

채점 준비의 검증 실행에는 기대 판정·실제 판정·일치 여부를 나란히 표시하고, 기존 제출과 동일한 코드·테스트 결과 상세와 다운로드를 제공합니다. 입력 검증기의 통과·거부 기대 및 실제 결과는 별도 표로 표시합니다. 준비용 코드 및 기록은 준비 탭 진입 시 조회하므로 문제풀이 첫 로드에 추가하지 않습니다.

기존 데이터에 용도 표시가 없으면 풀이 제출로 유지합니다. 기록의 이동 버튼 또는 `submission_classify`로 완료된 실행을 준비용/풀이 제출로 옮길 수 있습니다. 코드는 보존하며, 이전 실행의 기대 판정을 실제 판정으로 추정하지 않습니다. 현재 학습 데이터의 `verification.json`에 명시된 실행 ID는 `scripts/classify-preparation.py --storage-root .study/data --reports .study/preparation --apply`로 분류합니다. 스크립트는 원본을 보고서 옆 `classification-backup`에 보존하고 표시용 요약 캐시를 갱신하도록 무효화합니다.


## 채점 결과 목록과 상세

DOJ의 공개 채점 현황(https://doj.kr/ko/status)에서 겹치는 기능인 사용량·언어·코드 크기·시간·상세 흐름을 참고합니다. 이 앱의 채점 결과 및 전체 제출 기록에는 제출 ID, 판정, 통과 테스트 수, 최대 실행 시간·최대 메모리, 언어, UTF-8 코드 크기, 제출 시각과 상세 진입을 표시합니다. 수치형 점수와 공개 사용자 정보는 지원하지 않으므로 추가하지 않습니다. 제출 시각은 최근 제출에 상대 시간으로 표시하고 정확한 시각은 툴팁에서 확인합니다.

문제별 채점 결과에는 판정·언어 필터, 초기화 및 결과 새로고침을 제공합니다. 새 풀이를 제출하면 필터와 페이지를 초기화하여 최신 결과가 보이게 합니다. 상세는 판정 및 통과 테스트 수·최대 사용량·코드 크기 요약, 전체 결과/실패한 테스트 필터, 테스트 상세, 제출 코드 펼치기와 다운로드로 구성합니다. 준비용 기록 이동은 각 행의 기록 관리에 둡니다.

목록 응답의 time_ms, memory_kb, source_bytes, case_count, passed_count는 요약 캐시에 저장합니다. source_bytes는 UTF-8 바이트 수이며 사용량은 테스트별 최댓값입니다. case_count와 passed_count에서 컴파일 행(number=0)은 제외합니다. 아직 테스트 결과가 없는 실행의 시간·메모리는 null입니다. 기존 캐시의 수치가 없으면 요청 페이지의 기록만 읽어 캐시를 갱신합니다. 목록에는 코드·테스트별 결과·입출력을 전송하지 않습니다.
